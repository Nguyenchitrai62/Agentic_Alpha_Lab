## Ranked shortlist (most promising for 4h dip-reversion / 4h returns; history >= 2021-06 + strict timestamps)

1. **Bybit v5 funding + open interest + account-ratio (all majors, REST full history from 2020) + public trade archives (2020-03+).** Direct positioning/crowding gauges at 4h/8h; timestamps allow exact as-of joins. First follow-up: cross-venue funding dispersion (Bybit vs Binance-vision-implied) and OI-change x dip-depth interaction on `y1.0`.
2. **Binance metrics ZIPs (5-min OI + top-trader LS ratio + taker LS vol ratio, Dec-2020+, per major).** Only full-window venue-positioning panel found; ~11 KB/day/symbol keeps a 2021+ fetch to tens of MB. Needs +1d availability lag and per-symbol coverage check.
3. **Deribit BTC/ETH funding + DVOL (2019 / Apr-2021+).** Options-implied vol level/change and perp funding as fear/crowding controls; BTC/ETH-only but the two largest dip contributors. Skew/term-structure history has no endpoint (build = heavy per-instrument walk; defer).
4. **OKX bulk funding + trade history (2021/2022+, monthly zips, personal-use ToS).** REST is recent-only (~90-120d) so REST-only use is rejected; bulk pipeline is the viable path (adds a third funding venue + liquidation/trade tape for capitulation features).
5. **Wikipedia pageviews (daily, 2015+, all 5).** Coarse daily attention/retail-interest control; usable from D+1 bars. Weak for 4h dip timing, cheap to add as regime interaction.

Deprioritised: Hyperliquid (starts 2023-05, fails >= 2021-06; later useful as cross-venue check) /
GDELT (doc API throttled, bulk ~600 MB/day) / mempool.space fee history (current-only; block times fine) /
blockchain.com (BTC-only daily; possible later BTC control) / Binance options BVOL/EOH history (unprobed - verify endpoint first).

## As-of / causality notes (VF_COMMON conventions apply to follow-ups)

- Features at 4h bar `t` use only records with availability time <= bar close; fills use records strictly before `t_fill` (availability + stated safety lag, e.g. hourly funding stamped `h` usable from `h+1h`, daily files from next UTC day).
- Dev window for any follow-up study: `t_exit < 2025-09-14` rows of `fills_U.parquet`; never touch later data.
- Suggested safety lags: exchange funding/OI snapshots +1h; file-based series (Binance metrics, OKX bulk) +1d; Wikipedia +1d; GDELT (if ever) +2h.
