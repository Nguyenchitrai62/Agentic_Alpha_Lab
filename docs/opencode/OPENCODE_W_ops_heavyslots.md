Problem: several workers run 4-phase engine jobs at once (~0.5-1.5 GB each) and starve each other and the leader's own runs (host free RAM sat at 1.4-2.4 GB today). Build a cross-process heavy-job semaphore: `with heavy_slot("tag", max_slots=2, min_free_gb=2.5, poll=30, timeout_h=6):` - slot files under artifacts/research/heavy_slots/slot_<n>.lock held with an OS file lock (msvcrt on Windows, fcntl elsewhere) so a crashed process frees its slot automatically; acquire also waits until free RAM >= min_free_gb (psutil if installed in .venv, else PowerShell CIM fallback); writes holder info (tag, pid, start time) into the lock file; `python scripts/heavy_slot.py status` lists holders and free RAM; `python scripts/heavy_slot.py run --tag X -- <cmd...>` wraps a command. Priority: a `--leader` flag that takes a reserved third slot. Tests: two processes contend for one slot (second waits), crash releases (kill holder subprocess), status output, RAM gate with a monkeypatched reader.
